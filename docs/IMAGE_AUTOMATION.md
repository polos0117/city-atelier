# GPT 세션 이미지 작업 — 몫 없이, 잠금만

사람이 지켜보지 않는 GPT 세션이 빈 도시의 세계를 하나씩 차례대로 채우는 길이다. 사람이 지켜보는 세션은 `IMAGE_RULES.md` 그대로 한다(「올릴까?」).
원소 공방의 같은 문서(그쪽은 pkm 공방에서 — 사용자 2026-10-31 「pkm 공방처럼 gpt용 이미지 생성룰을 … 정의해줘」)를 도시 꼴로 다시 썼다(2026-11-20 — 그림 저장소 `city-atelier-img` · 기본 화풍 `kr_drawn_rim_dewy` · 서울 시험 그림에서 정한 것). 아래 도구 이름 · 칸 이름 · 갈래는 지금 코드(`tools/casual-plan.cjs` · `tools/prompt-pack.cjs` · `tools/image-claim.cjs` · `lib/prompt-city.js`)가 하는 그대로다.

도시 하나 = **세계마다**(판타지 · 스팀펑크 · 사이버펑크) 세계 그림 한 장 + 그 세계 그림을 붙인 **일상컷 열 장** — 장면 컷 여덟(필수 다섯: 그 도시 생활 장면 · 란제리풍 · 수영복 · 역할극 · 게임 코스프레, 보통 셋 — 그 가운데 한 장에 상황 노출) + 자유 설계 칸 둘(옷 자유 · 갈래 자유). 한 실행이 맡는 몫은 **한 도시의 한 세계**(`<도시>_<세계>`, 예 `seoul_fantasy` — 사용자 2026-11-20 「세가지 세계를 다 한 번에 만드는게 아니고 한 세계씩」): 세계 그림 한 장 + 일상컷 열 장 = 빈 자리 열하나(+ 캐릭터만의 컷 90번 하나 — `IMAGE_RULES.md` 2절). 랜드마크 카드(`seoul-haechi` 등)의 몫은 `<도시>-<랜드마크>_<세계>` — 같은 열한 장에서 **90번만 없고**, 일상컷의 생활 장면 · 계절 · 날씨는 부모 도시 것이다(계획기는 그 도시 카드끼리 덜 쓴 장면부터). 차례는 한 도시의 세 세계 → 그 도시 랜드마크(각 세 세계) → 다음 도시.

## 0-1. 세계 그림은 네 장 뽑고 멈춘다

세계마다 세계 그림 **네 장** — 우리 설계 `<세계>-prompt.txt` 두 장 + 임의 설계 주문 `<세계>-free.txt` 두 장(다른 공방과 같은 규칙 — 삼국지 · 원소 2026-11-09).
임의 설계 주문(`lib/prompt-city.js` `buildWorldFree` · `worldFillTemplate`, 글은 `lib/prompt-spec.js` `WORLD_FREE.fill`) — **2026-11-20 칸 채우기**(삼국지 공방 2026-11-18 · 11-19 에서 옮김 — 사용자 「칸 채우기로 옮겨줘」): 주문 아래 우리 설계 지시문을 통째로 주고 맡은 쪽은 표시한 칸만 채운다 — [HAIRSTYLE: …](우리와 다르게) · [COSTUME SILHOUETTE: …](그 세계 실루엣 목록에서 하나, 글 그대로) · Design idea(도시 상징 특징 하나를 의상 구조에) 는 반드시, [BUILD: …] 은 우리 체형 목록에서 하나를 글 그대로(우리 것 그대로도 된다), Face 줄은 얼굴 칸 여덟([IMPRESSION] · [SKIN TONE] · [FACE SHAPE] · [EYE SHAPE] · [EYE COLOUR] · [BROWS] · [NOSE] · [LIPS] — 칸마다 우리 목록에서 우리 것 말고 하나를 글 그대로, 두 장도 칸마다 서로 다르게, 웃는 입은 목록에 없다), 표정 줄은 고쳐도 되고, Stance and hands · Setting detail 은 채우거나 지운다. 나머지 줄(화풍 · 피부 마감 · 머리색 · 도시 motif · 세계 표지 · 색 · 소품 · 노출 · 세계 · 장면 · 자세 방향 · 빛 · 구도 · Avoid)은 글자 그대로. 두 장 다 첫 줄 SUMMARY: 다음에 채운 지시문 전체 — 그리기 전에 `node tools/world-fill-check.cjs <카드> <세계> <채운 글> --other <다른 장>` 이 통과해야 한다).
이 칸 채우기 전(2026-11-09 ~ 11-20)엔 맡은 쪽이 얼굴 · 헤어스타일 · 자세 · 장면 · 빛까지 지어 제 지시문을 썼다 — 우리 화풍 · 얼굴 규칙이 GPT 장엔 안 닿아 옮겼다. 채운 글은 기록 `generation.free_prompt` 에 통째로.
네 장을 「우리 설계 1 · 2 / GPT 설계 1 · 2」 로 보이고 **멈추고 묻는다** — 사용자가 고른 장만 올리고 그 장을 붙여 일상컷을 그린다(아래 0절 「묻지 않는다」 는 일상컷과 고른 뒤의 올리기에만 닿는다). 임의 설계 장을 고르면 기록 `generation.design: "gpt_free"` · `generation.free_prompt`.
GPT 설계 기록(2026-11-26 사용자 「꼴 맞추는게 나을거 같아 1-4 다 해줘」 — 네 공방 같은 꼴): `generation.design: "gpt_free"` · `generation.free_prompt`(**GPT 가 채운 지시문 통째 — 주문서 `-free.txt` 가 아니다**) · `generation.summary`(GPT 가 맨 앞에 쓴 `SUMMARY: hairstyle …; …` 한 줄 그대로) · `generation.hair_family`(주문서 「Hairstyle direction」 의 그 설계 갈래 — 설계 1 이면 첫째). 주문서는 설계마다 머리 갈래를 정해 준다(`fill.family` · `hairFamilies` — 카드 · 세계로 돌려 가며 우리 설계 갈래는 빼고, 어깨 위로 푼 머리 + 옆 앞머리 · 머리 장식 기본값은 막는다). 원소 GPT 세계컷 38장은 어깨~가슴 길이 푼 머리, 도시 56장은 허리까지 푼 웨이브 + 머리 장식으로 쏠렸고, 기록 대부분이 주문서만 남겨 GPT 가 고른 머리를 셀 수 없었다.

일상컷 열 장 중 두 장은 **자유 설계 칸**(원소 2026-11-11 꼴 그대로 — 사용자 「장소·활동·자세·구도·의상을 자유롭게 설계해줘 …」) — 계획기 `makeFree`, 장면 칸 `sfree`:
**옷 자유 칸**(`ofree` — 묶는 것 없음)과 **갈래 자유 칸**(`gfree` — 필수 노출 갈래 하나(셋 가운데 다른 세계 묶음이 덜 쓴 것, 큰 범위만 — 목록에 없는 옷 먼저 · 그 갈래 필수 컷의 옷은 아닌 것 — 장면 칸 `gnot`, 지시문 「Not the same outfit as the one already in this set」) + 열린 상황 하나(`gsitu: 'free'` — 우리 상황 표에 없는 것 먼저)를 둘 다). 지시문에 장면 줄 대신 `FREE DESIGN:` 덩어리(`T.FREE_DESIGN`)가 있다 —
**자유 설계 덩어리를 채운다**: 그 사람(첨부 그림 · 지시문의 그 도시 줄)에서 출발해 장소 · 활동 · 자세 · 구도 · 의상을 지어 덩어리의 「…」 줄(Place · Activity · Pose · Framing · Outfit)을 채운 뒤 그린다. 「Recent scenes to avoid」 와 비슷한 장면은 피하고, 옷은 묶음의 `outfit-catalog.md`(우리가 쓰는 옷 전부)에 없는 것, 갈래 자유 칸은 `Outfit family (required)` · `Situation (required)` 두 줄을 둘 다 지킨다. 덩어리 밖의 줄(얼굴 · 화풍 · 몸 · 세계 줄 · 첨부 그림)은 낱말 하나 고치지 않는다.
장소도 그 세계의 그 도시다 — 판타지 · 스팀펑크 칸에 지금 물건(스마트폰 · 플라스틱 · 전광판 …)을 들이지 않고, 세계 줄이 말하는 결로 장소를 짓는다(명소 · 하늘 풍경은 장소가 말할 때만).
채운 글은 기록에 남긴다 — `generation.free_prompt`(실제로 넘긴 지시문 통째) · `generation.free_design`(채운 덩어리). `casual-plan.cjs --check` 가 없거나 「…」 그대로면 잡는다.

### 선택 시트 기본 화질

- 세계컷 선택 시트는 세계와 번호를 표시한 한 장으로 만든다. 각 컷은 원본 **1024×1536 픽셀을 축소 없이** 배치하고 PNG 무손실로 저장한다. 512×768 썸네일을 기본 시트로 쓰지 않는다.
- 4열 × 3세계 시트는 그림 영역만 4096×4608 픽셀이며, 여백·세계명·번호 공간을 더해 저장한다. 전체 시트를 먼저 축소한 뒤 확대하지 않는다.
- 원본 이미지의 픽셀과 구도를 유지하고 라벨은 그림 바깥에 둔다. 채팅 미리보기와 별도로 원본 해상도 시트 파일을 제공한다. 시트는 그림 저장소에 올리지 않는다.

## 0. 승인 — 묻지 않고 올린다

다른 공방과 같다(pkm · 원소 — 사용자 2026-10-31): **중간에 묻지 않고, AI 검수(QA) 뒤 바로 올린다. 그림의 시각적 품질은 올라간 뒤 사용자가 본다.** 단 세계 그림 네 장은 0-1 대로 멈추고 묻는다.
그래서 GPT 세션에서는 `IMAGE_RULES.md` 1절의 다음 둘이 바뀐다.

| IMAGE_RULES(1절) | GPT 세션 |
|---|---|
| 올리기 전에 사람이 본다 — 「올릴까?」 | 묻지 않는다. 아래 4절 검수를 적고 올린다 |
| 계획대로 안 나오면(스팀펑크에 그을음 · 사진 질감이, 판타지에 지금 물건이, 사이버펑크가 오늘의 도시 + 네온으로) 원인을 적어 먼저 묻는다 | 묻지도, 고쳐 다시 그리지도 않는다. 어긋난 데와 원인을 검수 기록에 적고 올린다 |

이 승인이 닿지 **않는** 것 — 그때는 그 자리에서 멈추고(5절 block) 보고한다:
안전 필터 거절이 `IMAGE_RULES.md` 1절 순서(같은 지시문 한 번 → 노출 한 단계씩 → 계획 바꾸기 한 번)를 다 밟고도 남을 때, 결과가 불분명한 응답, 원본을 잃음, 도구 오류,
다른 세션의 잠금, 받은 그림이 그 자리의 크기(세계 그림 1024×1536 · 일상컷은 `INDEX.md` 「크기」)가 아님(같은 비율로 더 크게 온 것 — 1:1 1254×1254 등 — 은 맞다. 한 번 더 — 그래도 아니면 멈춤), 이미 있는 파일 이름, 노출을 적게까지 낮춰도 가슴 끝이 비침(4절).
**그림 속 글자 · 숫자는 멈출 까닭이 아니다**(사용자 2026-11-21 「숫자나 글자보인다고 업로드 보류하는 것좀 없애줘」) — 보이면 `qa.observations` 에 적기만 하고 그것 때문에 `passed: false` 로 하지도, block 하지도, 다시 그리지도 않고 올린다. 로고 · 워터마크 · 말풍선은 4절대로 `passed: false` 와 함께 적고 올린다(이것도 block 이 아니다).
이미 올라간 그림을 덮거나 지우는 일, 강제 push, 이력 재작성은 어떤 경우에도 하지 않는다.

## 1. 준비

- `AGENTS.md` · `IMAGE_RULES.md` 를 먼저 읽는다. 코드(`city-atelier`)와 그림 저장소(`city-atelier-img` — 그림은 `img/`, 기록 · 잠금은 `records/`)를 **나란히**(같은 부모 폴더에) 받아 최신 `main` 으로 둔다 — 도구들이 `../city-atelier-img` 로 찾는다.
  남의 로컬 변경을 reset 하지 않는다.
- Node 와 Python 3 + Pillow 가 있으면 된다. **브라우저는 쓰지 않는다** — 생성기 화면 대신 지시문 묶음(`tools/prompt-pack.cjs`)이 같은 글을 파일로 준다
  (`tests/prompt-pack-screen.cjs` 가 세계 그림 · 일상컷 자리를 실제 화면과 글자 하나까지 견준다).
- 실행 ID 를 **한 번** 정하고 이 실행의 모든 명령에 그대로 쓴다. 부모 작업이 준 호출 ID 가 있으면 그것.

```sh
export ATELIER_EXECUTION_ID="city-$(date -u +%Y%m%dT%H%M%SZ)"
node tools/image-claim.cjs status                      # 잠금 · 다음 차례(읽기만)
```

`status` 에 「빈 자리 없음 — done 으로 끝낸다」 가 붙은 잠금이 있으면 그것부터 `done` 한다(앞 실행이 등록을 기다리다 끝났다 — 6절).

## 2. 차례와 잠금

```sh
node tools/image-claim.cjs next                         # 다음에 그릴 몫(도시 · 세계)과 빈 자리
node tools/image-claim.cjs claim <도시>_<세계> --execution $ATELIER_EXECUTION_ID
```

- 차례는 설계표 차례(서울이 처음) × 세계 차례(판타지 → 스팀펑크 → 사이버펑크)다 — 한 도시의 세계를 다 그린 뒤 다음 도시로(`IMAGE_RULES.md` 2절). 설계 전 도시(`worlds` 가 빈)는 몫이 없다. 고르는 것은 도구가 한다.
- **하루 · 실행마다의 몫이 없다**(다른 공방과 같다). 한 실행이 여러 몫을 차례로 잡아도 된다. 「몫」 은 한 도시의 한 세계다.
  잠금은 그대로다 — 다른 세션이 잡은 몫은 건드리지 않고, 한 몫을 끝내거나 멈춘(block) 뒤 다음 몫을 잡는다. 그림 저장소가 900 MB 를 넘으면 썸네일 워크플로가 경고한다(Pages 1 GB) — 그때는 다음 그림 저장소를 연다(`IMAGE_RULES.md` 3절).
- 잠금은 그림 저장소 `records/automation/claims/<도시>_<세계>.json` 하나다. `claim` 은 그 파일만 커밋해 일반 push 한다 —
  다른 세션이 먼저 밀었으면 거절되고 도구가 제 커밋을 되돌린다. 그때는 pull 하고 `status` 부터 다시.
- 잡힌 몫(`working` · `blocked`)은 시간이 지나도 가져가지 않는다. `blocked` 는 사용자가 정한 뒤 `release` 로만 푼다.
- 한 몫의 빈 자리 = 그 세계의 세계 그림 · **일상컷 열 장**(기본 화풍 — `data/style.json` default, `data/img.json`). 열 장보다 적은 세계는 모자란 만큼만 더 그린다 — 계획기가 그 번호만 짠다.
  번호는 **세계마다 따로** 비어 있는 가장 작은 것부터 — 이름에 세계가 있어 세계끼리 번호가 겹쳐도 된다(`claim` 이 적어 준 `missing` 그대로). 캐릭터만의 컷(90번)은 열 장 수에 세지 않는다.

## 3. 계획과 지시문 묶음

작업 폴더(`$W`)는 세션 임시 자리에 둔다. 잡은 세계의 계획부터:

```sh
node tools/casual-plan.cjs <도시> --world <세계> --records ../city-atelier-img/records/<도시> --out $W/plan-<세계>   # --slots 를 안 주면 그 세계의 빈 번호
node tools/prompt-pack.cjs init <도시> --dir $W/pack --plan $W/plan-<세계>/plan.json   # 잡은 세계 하나
node tools/prompt-pack.cjs build --dir $W/pack                                  # 자리마다 <자리>-prompt.txt · <자리>-ui.json, 세계 그림 자리는 <세계>-free.txt 도 · outfit-catalog.md · INDEX.md
```

- 일상컷은 **트리 버전2**(공용 모듈 `lib/casual-tree-v2.js`)에 이 공방의 생활 장면표(`data/city-life.json`) · 세계 소품 사전(`data/world-props.json`)을 얹어 짠다. 일상컷은 그 세계의 그 도시의 하루라 시대는 곧 세계다(원소의 「네 시대 · 나라 안 갈래」 는 없다).
  계획기가 세계 묶음 규칙(`tools/casual-plan.cjs` 머리말)을 지킨다 — 필수 다섯(그 도시 생활 장면 한 장 — 가장 먼저 정한다 · 란제리풍 · 수영복 · 역할극 · 게임 코스프레) · 보통 셋 가운데 한 장에 상황 노출 · 장소 겹침 없음(생활 장면 · 일반 장소 통틀어) · 먼/가까운 컷 하나씩 · 그 도시의 물건(설계표 `hold`)을 든 컷 한두 장 · 소품 고르게 · 판타지 · 스팀펑크는 그 세계 금지 낱말이 든 옷 · 어색한 소품 동작(`not_uses`)을 안 고른다 · 다른 도시에서 안 쓴 장소 · 옷 · 자세 · 표정 먼저 ….
  **장소 풀은 섞는다**(2026-11-20 사용자 「서울 장면은 일반장소랑 섞어 쓰면서 또 하나의 필수 컷으로」 · 「필수칸 두고 전부 섞자」): 그 도시의 생활 장면(`data/city-life.json` — 장면의 그 세계 글 · 그 세계 소품) ∪ 일반 장소(`data/casual-tree.json` places, 시대 now — 장소 글 그대로 싣고 「World:」 줄이 그 세계로 바꾼다). 칸마다 그 칸의 의상 계열을 받는 곳만, 반쯤 생활 장면 먼저 · 아니면 일반 장소 먼저(고른 쪽이 비면 다른 쪽). 판타지 · 스팀펑크는 글에 그 세계 금지 낱말(`banned_en`)이 든 일반 장소를 안 쓴다. 세계끼리 같은 장소는 옷 계열이 다를 때만(노출 갈래 · 코스프레 칸은 남은 곳이 없으면 같은 계열도).
  그림 저장소 기록을 읽어야 하니 `--usage none` 은 쓰지 않는다(기본이 옆의 `city-atelier-img/records`). 게임 코스프레의 쓴 것도 그 저장소에서만 읽는다 — 저장소가 없으면 계획기가 멈춘다(`--cosplay-usage none` 은 시험 때만).
  GPT 세션은 계획을 사람에게 보이지 않는다 — 계획기 출력 그대로 간다. 이미 있는 컷의 기록(`--records`)은 겹침 검사에만 쓴다.
- 일상컷 지시문의 「World:」 줄은 세계의 결(`vocab.casual_world.<세계>.en`)과 그 다음 막는 줄(`guard_en` — 명소 · 하늘 풍경은 장소 줄이 말할 때만)이다. 고치지 않는다.
- `settings.json` 은 **비워 둔 채** build 하는 것이 기본이다. 고칠 때만 칸을 채우고, 직접 입력(덧붙임 글 · 표에 없는 외형)엔 `why` 를 적는다.
  틀린 칸이 하나라도 있으면 build 가 아무것도 안 쓴다. 고칠 수 있는 칸은 `tools/prompt-pack.cjs` 머리말에.
- **`<자리>-prompt.txt` 를 손으로 고쳐 내지 않는다.** 고칠 것이 있으면 settings 를 고쳐 build 를 다시 돌린다. 예외는 자유 설계 칸의 덩어리 「…」 채우기 · 임의 설계 주문의 칸 채우기(0-1) — 덩어리 밖은 그대로.
- 노출을 낮춰 다시 그릴 때(필터 거절)는 settings 의 그 자리만 고친다 — 세계 그림은 `worlds.<세계>.look.exposure`, 일상컷은 `casual.<자리>.exposure`(`moderate` · `low`, `why` 에 까닭) — 그리고 build.
- 이미지 도구가 일상 한 칸을 막아(같은 지시문 두 번 · 노출 보통 · 적게까지 다 막혀 — `IMAGE_RULES.md` 1절) 다시 정할 때는 그 칸만 `--slots N --seed <다른 씨앗>` 으로 계획기에 다시 맡기고
  `--records` 에 나머지 기록을 준다 — 그것도 한 번만. 새 계획에서도 같은 지시문 한 번 · 노출 낮추기를 밟고, 다시 막히면 5절.
- **게임 코스프레 컷**(원소 공방 2026-11-15 ~ 11-17 에서 옮김 — 사용자 2026-11-20 「게임 코스튬도 필수로 했었는데 그게 없네?」): 의상 자체가 그 게임 캐릭터를 드러내는 코스튬 컷(그녀가 그 캐릭터의 코스프레를 입은 것 — 얼굴 · 머리색 · 몸은 첨부 그림 그대로). 목록 `data/game-cosplay.json`(원본 game-atelier — 고치지 않는다, 옆에 있으면 다를 때 계획기가 경고).
  계획기가 게임(남은 인원의 제곱근 무게) · 캐릭터(등장인물 많은 게임은 안 쓴 캐릭터 — 여자 2 · 남자 1 무게, 다 쓰면 2회차) · 재단(열하나 — 그 게임에서 덜 쓴 것)을 정해 장면 칸 `cosplay = { game, character, cut, round }` 에 적고, 장소는 코스프레 행사 · 테마 행사장 · 오락실 · 거실 · 침실 · 댄스 무대(비키니 · 원피스 수영복 재단이면 물가도), 얼굴 클로즈업 아님. 옷 색 · 데니어 · 상황 · 세계 평상복 결은 얹지 않는다.
  「쓴 것」 = 이 공방 그림 저장소(`city-atelier-img`)의 그린 기록 `generation.cosplay` + 아직 안 그린 계획 파일(`<세계>-casual-plan.json`)의 예약. 그래서 그린 뒤 기록에 **`generation.cosplay = { "game", "character", "cut" }`**(계획 그대로)을 꼭 남긴다.
- 올리기 전에 `node tools/casual-plan.cjs <도시> --world <세계> --check <이 도시의 기록 폴더>` 가 통과해야 한다(새 기록을 넣은 사본으로 본다 — 자유 설계 칸 기록엔 7절의 `generation.free_prompt`, 게임 코스프레 칸 기록엔 `generation.cosplay` 까지 넣은 뒤 — 없거나 계획과 다르면 잡는다).

## 4. 그리기와 검수

- `INDEX.md` 의 차례대로, **`claim` 의 `missing` 에 있는 자리만** 그린다. 자리 하나에 생성 호출 한 번. 자유 설계 칸(INDEX 「덩어리 채우기」)은 덩어리를 채운 지시문으로 그리고, 그 글을 기록 `generation.free_prompt` · `free_design` 에 남긴다(0-1).
- 세계 그림은 **기준 그림 없이** 한 장씩(세계마다 다른 사람이다), 네 장 뽑고 멈춘다(0-1). 일상컷은 고른 세계 그림을 **꼭** 붙인다(이미지 편집 — 첨부 없이 뽑으면 다른 사람이 된다).
  이 세션에서 받은 원본, 이미 등록된 세계 그림이면 그림 저장소의 `img/<파일>.webp`. 세계 그림이 없는 세계는 일상컷을 그리지 않는다.
- 이미지 도구에 크기 설정이 있으면 **그 자리의 크기**로 준다 — 세계 그림 1024×1536, 일상컷은 `INDEX.md` 「크기」 칸(= 계획 `scene.aspect` — 2:3 1024×1536 · 1:1 1024×1024 · 3:2 1536×1024, 2026-11-23). 도구가 실제로 돌려준 파일만 쓴다.
- 받은 뒤 **AI 검수**를 적는다(기록의 `qa` — 7절). 본 것을 구체적으로:
  - 그 자리의 크기인가(세계 그림 1024×1536, 일상컷은 `INDEX.md` 「크기」 — 계획이 3:2 인데 세로로 왔으면 다시 · 같은 비율로 더 크게 온 1:1 1254×1254 등은 맞는 크기 — 비율이 다를 때만 다시) · 그녀 한 명(배경 흐린 사람은 괜찮다) · 로고 · 워터마크 · 말풍선 · 그림에 틀이 없나. 글자 · 숫자는 보이면 적기만 한다(걸림 아님 — 0절, 2026-11-21).
  - **화풍** `kr_drawn_rim_dewy` 의 결대로인가 — 그린 얼굴 · 2D 붓 칠(보이는 붓결 · 가는 색선) · 림 라이트 · 몸 피부 물광(어깨 · 팔 · 쇄골 · 다리 — **얼굴은 물광 없음**). 사진 같은 실사 · 3D 렌더 · 평면 셀 애니로 새지 않았나.
  - **사람** — 그 나라의 성인 여성인가, 미형인가, 같은 도시의 다른 세계 그림과 얼굴이 겹치지 않나(세계 그림).

  - **팔·다리·손의 수와 이어짐**.
- 몸 이상은 `qa.anatomy` 에 따로 적는다: `ok` 또는 걸린 것의 목록 `["arm", "hand", "foot", "leg"]`(추가 · 끊긴 · 떠 있는 · 뒤바뀐 팔은 arm, 손가락 수 · 떠 있는 손은 hand, 발 · 발 윤곽은 foot, 다리는 leg) — 무엇을 봤는지는 `observations` 에. 이미 쓴 기록은 고치지 않는다.

  지시문에서 부딪힌 줄(세계 · 장소 · 의상 · 자세 · 프레이밍 · HAND · ANGLE · WARDROBE)을 찾았으면 원인도 적는다 — 규칙 · 계획기 · 설계표를 고치는 일은 사람이 지켜보는 세션이 한다.

## 5. 멈춤

```sh
node tools/image-claim.cjs block <도시>_<세계> --execution $ATELIER_EXECUTION_ID --reason '실제 까닭(어느 자리 · 무슨 응답)'
```

- 0절의 「닿지 않는 것」 이면 그 자리는 그리지 않고 block 한다. 그 전까지 검수한 자리는 6절대로 올려도 된다(빈 자리를 줄인다).
- 거절된 지시문은 sha256 과 함께 기록 폴더에 `<자리>.blocked.json` 으로 남긴다(지시문 · 시도 수 · 응답 코드). 그 지시문을 바꿔 다시 시도하지 않는다.
- block 된 몫은 사용자가 정할 때까지 잠긴 채다. 사용자가 정하면 사람이 지켜보는 세션이 `release --approval '<사용자 말>'` 로 푼다.

## 6. 올리기와 끝

1. 자리마다 원본을 WebP(품질 90, method 6, 세계 그림 1024×1536, 일상컷은 그 자리의 크기 — 이미 그 크기면 원본 크기 그대로, 같은 비율로 더 크게 온 원본(ChatGPT 화면의 1:1 1254×1254 등)은 그 크기로 줄인다(LANCZOS, 2026-11-23))로 바꾼다. 이름은 `INDEX.md` 의 「올릴 파일」(= `IMAGE_RULES.md` 3절). 같은 이름이 그림 저장소에 이미 있으면 멈춘다 — 덮지 않는다.
2. 그림 저장소에 **한 몫 한 커밋**으로 일반 push 한다: `img/<파일>.webp` 들과 `records/<도시>/` 의 기록 —
   세계 그림은 `<세계>.<화풍>-ui.json`, 일상컷은 `<세계>-casualN.<화풍>-ui.json`(묶음의 `<자리>-ui.json` 을 이 이름으로 — 안의 `record` 칸이 그 자리다), 일상 계획은 `<세계>-casual-plan.json`.
   기록 JSON 에 7절의 `generation` · `qa` 칸을 더한다. **원본 PNG 는 올리지 않는다** — sha256 만(그림 저장소 `.gitignore` 가 `*.png` 를 막는다). 썸네일 · `data/img.json` 은 손으로 만들지 않는다(워크플로가 한다).
3. push 가 밀리면 pull --rebase 한 번. 그 사이 같은 파일 이름이 들어왔으면 멈추고 보고한다.
4. 그림 저장소 Actions 의 `썸네일` 이 초록인지(「코드 저장소 깨우기」 notice), 코드 저장소에 `그림 등록` 커밋이 생겼는지 본다(깨우기가 안 닿아도 `그림 등록` 은 한 시간마다 돈다).
5. 코드 저장소를 pull 한 뒤 끝낸다. 등록이 아직이면 잠금을 `working` 으로 두고 실행을 마친다 — 다음 실행의 `status` 가 끝내라고 알려 준다.

```sh
node tools/image-claim.cjs done <도시>_<세계> --execution $ATELIER_EXECUTION_ID
```

`done` 은 `data/img.json` 에 그 세계의 빈 자리가 없어야 된다(세계 그림 + 일상컷 열 장).


## 8. 하지 않는 것

- 브라우저로 생성기를 조작하지 않는다 · 다른 유료 API 나 새 자격증명을 쓰지 않는다 · 계획 · 지시문을 손으로 고쳐 내지 않는다(자유 설계 덩어리 채우기 · 임의 설계 칸 채우기만 예외).
- 남의 잠금 · 기록 · 그림을 고치지 않는다 · 검수 실패를 통과로 바꾸지 않는다 · 같은 자리를 여러 번 다시 그려 고르지 않는다(필터 거절의 순서 · 몸 이상 다시 그리기만 예외) · 화풍을 바꾸지 않는다(늘 기본).
